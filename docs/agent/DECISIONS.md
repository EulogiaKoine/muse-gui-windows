# 결정 기록 (이유와 함께 남긴다. 새 결정은 맨 위에 추가)

## 2026-11-26 · main beautify 보류 (오프라인에 도구 없음)

- beautify용 라이브러리(prettier 등)가 오프라인 환경에 없고 설치도 불가하다.
- 수작업 beautify는 토큰 비용·회귀 위험이 크고, 반만 적용하면 일관성이 깨진다.
- 따라서 main은 dev와 동일한 코드로 병합하고, beautify는 도구 확보 후 별도 작업으로 둔다.

## 2026-11-26 · dev-agent 분리 안 함

- 검토: 에이전트 전용 청크 분할·파이프라인 최적화를 위한 별도 브랜치.
- 판단: 수행하지 않는다.
- 이유: 사람 기준 분할 후 파일이 3~21KB가 되어 에이전트 작업 단위도
  이미 충분히 작다. 별도 브랜치는 병합 충돌·드리프트·이중 검증을
  만들 뿐 가시적 이득이 없다. `static/INDEX.md` + 모듈 주석으로
  필요한 파일을 바로 여는 방식이 토큰·정확도 모두 낫다.
- 대안 유지: 단일 `dev`에서 작업하고, 필요하면 그때 다시 검토한다.

## 2026-11-26 · 정적 분할은 이동 위주, 동작 변경 없음

- `static/app.js`(3021행) → `static/js/*.js`(12개),
  `static/style.css`(426행) → `static/css/*.css`(6개).
- 바이트 단위 동일성 + 하네스 + 실측 프로브로 검증했다.
- 예외적 이동 2건(둘 다 script가 검증): `applySide`·`setSide` →
  `ui.js`, `copyText`·`flashCopy` → `chat.js`.
  이유는 모듈 책임 일치. 동작은 호출 시점 바인딩이라 동일하다.

## 2026-11-26 · 테스트는 모듈 전체 로드 방식

- 구 방식(단일 파일에서 문자열 구간 슬라이스)을 버렸다.
- `render.test.js`는 `util.js`+`icons.js`+`render.js` 전체를,
  `usage.test.js`는 `usage.js` 전체를 로드한다.
- 이유: 구간 앵커는 파일 분할과 양립할 수 없고, 모듈 전체 로드가
  더 단순하고 정확하다.

## 2026-11-26 · persistConvs는 실패해도 메모리를 건드리지 않는다

- 배경: 저장 실패 시 `pop()`으로 오래된 대화를 날리던 코드가
  현재 대화를 증발시켜 pick-new 게이트+하이라이트 소실을 일으켰다.
- 대책: 슬림 저장(추론 상세 축소) → 그래도 실패하면 1회 경고.
  인메모리 목록은 절대 변경하지 않는다.

## 2026-11-26 · 게이트: sid가 있으면 항상 resume

- 디렉터리 요구는 sid 없는 새 대화에서만 나온다.
- cwd가 비어 있으면 서버 기록에서 복원한다(입수 포함).
- 이유: 기존 세션 진입이 항상 채팅+재실행 버튼이어야 한다는 요구.

## 2026-11-26 · dev-agent 통합 절차(에이전트 작업 격리)

- dev-agent 브랜치에서만 `docs/agent/`를 버전 관리한다.
  (해당 브랜치의 `.gitignore`는 루트 `AGENTS.md`만 무시한다.)
- dev-agent → dev(→ main) 방향으로 통합할 때는 병합 대상에서
  `.gitignore`와 `docs/agent/`를 제외한다:
  `git merge --no-commit --no-ff dev-agent` 후
  `git checkout <target> -- .gitignore` 로 되돌리고
  `git rm -r --cached docs/agent` 로 인덱스에서만 제거한 뒤 커밋한다.
  이렇게 하면 워킹트리의 문서는 남고, 대상 브랜치에는 코드 변경만 들어간다.
- 코드 변경이 dev-agent에 실수로 들어간 경우, 통합 전에 해당 파일만
  `git checkout <target> -- <path>` 로 되돌리거나 체리픽 방식을 쓴다.
